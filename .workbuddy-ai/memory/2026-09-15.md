## 排查:线上状态页"行情数据距今 46 天"(as_of 冻结在 2026-07-31)

**根因**:`ECY`(实际利率口径)是唯一在 7/31 之后整列 NaN 的估值分项 → 拖垮 `V → base → heat_pct`
→ `daily_status.py` 的 `as_of = 最后一天 heat/CAPE/Buffett 同时非 NaN` 就锁死在 2026-07-31。
Actions 与行情抓取其实都正常(页面 `generated_at` 是当天)。

**为什么 ECY 会在 7/31 之后断供**:
`daily_in_monthly_window_pct(lag=1)` 要求"上月"必须存在于月度序列。ECY 的月度序列来自
`h15_all.zip`(H.15 TIPS,`RIFLGFCY10_XII_N.B`),该文件只到 2026-06-10 → 月度止于 2026-06
→ 最后能算的月份是 2026-07。该 zip 属"需手工维护"清单,上线后从未更新。

**叠加故障**:`fetch_data.py` 对所有站点统一用 Chrome UA,而 **FRED 会掐断浏览器 UA 的请求**
(Chrome UA 超时 / 默认 UA 与 curl UA 秒回)。因此 FRED 从上线起就没抓成功过:
`fred_CPIAUCSL.csv`、`macrotrends_high_yield_spread_D.json` 自 2026-06-12 后再未变化。
旁证:修复后同一流程耗时 **~200s → 19s**,那 200s 原本是 FRED 超时重试空转。

**静默降级(易被忽略)**:`v25.reweight()` 对缺项按剩余权重静默归一,分项断供不报错:
`PutCall` 停在 2026-06-11、`BreadthU` 停在 2026-06-12、`VIXTerm` 停在 2026-08-03
(`^VIX3M` 在 Yahoo 已废,3 个月窗口只返回 23 行、止于 2026-07-17)。

## 排查方法论(下次可直接复用)

1. 先比 `status.json` 的 `generated_at` 与 `as_of`:generated 是新的 → 任务没停,是数据链问题。
2. 用 `curl` 拉 `codeload.github.com/.../tar.gz/refs/heads/main` 拿**仓库快照**(含 Actions checkout 的真实缓存),
   在临时目录跑 `build_core()`,逐列打印最后非 NaN 日期 → 直接定位是哪一列先死。
3. 查 GitHub API `commits?path=<cache 文件>`:哪个缓存"自某天起再没变过"就是哪个源坏了。
4. 对比各 run 的步骤耗时:耗时异常长往往是某个源在超时重试空转。
